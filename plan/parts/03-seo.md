# 03. SEO и локальный поиск — часть плана продвижения ВОЛЬТ (90 дней)

**Зона:** семантика, структура сайта, on-page, микроразметка, локальное SEO,
технический минимум. Вне зоны: SMM-контент, платный трафик, сквозная аналитика
воронки (см. соответствующие части общего плана).

**Сайт:** volt-rent.netlify.app · **Город:** Красноярск (доставка) · **Пункты
выдачи:** Братск, Усть-Илимск, Нижнеудинск · **Бренд инструмента:** APEXWOLT.

## 0. Стартовый срез: что сейчас на сайте

Быстрая проверка (WebFetch по главной, `/catalog`, `/robots.txt`) показала:

| Находка | Статус | Значение |
|---|---|---|
| `robots.txt` | 404 — отсутствует | нет управления обходом, риск случайной индексации служебных URL в будущем |
| `sitemap.xml` | не найден | поисковики находят страницы только через ссылки — медленная индексация |
| H1 главной | «Сила в аренду» | сильный слоган, но без ключевого запроса — нужен баланс бренд/спрос |
| Title / meta description | не заданы явно | критично — нулевой CTR-потенциал в выдаче |
| Категории инструмента (перфораторы, УШМ и т.д.) | не имеют отдельных URL | весь спрос по типам инструмента сейчас никуда не собирается |
| `/catalog` | рендерится как SPA-состояние («в категории пока нет позиций» видно даже боту) | **высокий риск**: если каталог собирается через JS без пререндера/SSG, часть контента может быть невидима для поисковых роботов |
| Гео-страницы (Красноярск, Братск, Усть-Илимск, Нижнеудинск) | отсутствуют | весь локальный спрос вне брендового трафика теряется |
| Schema.org | не обнаружена в статическом HTML | нет расширенных сниппетов, нет структурных сигналов для ИИ-поиска |
| Blog/FAQ | отсутствуют | нет информационного трафика и охвата «как выбрать / сколько стоит аренда» |

Вывод: сайт в базовом состоянии — «визитка + каталог», без SEO-фундамента.
90-дневный план ниже закрывает это по фазам, от критичного к усиливающему.

через Яндекс.Wordstat и Google Keyword Planner по гео «Красноярск» — это

  шуруповёрт) и на `/faq`.

  входящие ссылки с уже проиндексированных страниц в первую неделю после
  публикации.

## 3. On-page: шаблоны

### 3.1 Категория (`/catalog/{категория}`)

- **Title:** `Аренда {инструмент, мн.ч} в Красноярске — прокат от [цена] ₽/сутки | ВОЛЬТ`
  Пример: «Аренда перфораторов в Красноярске — прокат APEXWOLT с доставкой | ВОЛЬТ» (≤60 симв.)
- **Meta description:** «Аренда {инструмент} APEXWOLT в Красноярске: посуточно, на неделю, на месяц. Бесплатная доставка от 3 дней, возвратный залог. Оформление за 5 минут.» (150–160 симв.)
- **H1:** `Аренда {инструмент} в Красноярске`
- **Обязательные блоки текста (300–500 слов, не «вода»):**
  - 1 абзац: для чего берут этот инструмент (DIY vs профи), под какие задачи;
  - блок сроков и цен (или «цена по запросу» с явной ссылкой на прайс, если
    цифр нет на момент публикации — **цены не выдумываем**);
  - блок «что входит» (комплектация: сверла/диски/оснастка — если это
    реальная практика ВОЛЬТ);
  - блок доставки/залога с явной формулировкой оффера (доставка бесплатно
    от 3 дней);
  - мини-FAQ (3–4 вопроса) с `FAQPage` разметкой (раздел 4).
- **H2/H3:** по подкатегориям/моделям, сравнению («какой {инструмент}
  выбрать»), сроки аренды.

### 3.2 Карточка товара (`/catalog/{категория}/{товар}`)

- **Title:** `{Модель} APEXWOLT в аренду — от [цена] ₽/сутки | ВОЛЬТ Красноярск`
- **Meta description:** характеристики + оффер в 150–160 симв., например:
  «Прокат {модель} APEXWOLT: мощность {X} Вт, {доп. характеристика}. Аренда в Красноярске с доставкой от 3 дней, залог возвращается.»
- **H1:** `{Модель} APEXWOLT — аренда`
- Обязательно: реальные технические характеристики (не выдумывать),
  фото товара с alt-текстом вида «перфоратор APEXWOLT {модель} — аренда в Красноярске», блок цен по срокам (сутки/3 дня/неделя/месяц), кнопка заказа
  (в Telegram-бот заказа), блок «для кого подойдёт» (частник/профи).

### 3.3 Гео-хаб `/krasnoyarsk`

- **Title:** `Аренда инструмента в Красноярске — прокат APEXWOLT с доставкой | ВОЛЬТ`
- **Meta description:** «Прокат перфораторов, УШМ, шуруповёртов и другого инструмента APEXWOLT в Красноярске. Бесплатная доставка при аренде от 3 дней, возвратный залог.»
- **H1:** `Аренда и прокат инструмента в Красноярске`
- Блоки: карта зоны доставки, список категорий со ссылками, оффер-блок,
  отзывы (если есть), FAQ, схема LocalBusiness (раздел 4).

### 3.4 Пункт выдачи `/punkty-vydachi/{город}`

- **Title:** `Аренда инструмента в {город} — пункт выдачи ВОЛЬТ`
- **H1:** `Прокат инструмента в {город}`
- Блоки: адрес и режим работы пункта, топ-3 категории со ссылками, условия
  (самовывоз/бронирование), FAQ по локальной специфике.

### 3.5 FAQ `/faq`

Собрать в один свод все возражения: залог, доставка от 3 дней, сроки
аренды, что при поломке, документы. Использовать как источник для
`FAQPage`-блоков на страницах категорий (можно дублировать 3–4 вопроса
локально + ссылка на полный FAQ).

### 3.6 Общие требования к текстам

- Не переспамливать «аренда/прокат» — использовать оба синонима естественно.
- Каждая страница — уникальный текст, не шаблон с заменой только названия
  категории (риск тонкого контента при масштабировании на карточки).
- Указывать Красноярск в первых 100 словах текста категории/гео-страницы.
- Цены и точные цифры — только из карточек сайта/прайса; если данных нет —
  «по запросу» или «уточняйте при заказе».

## 4. Микроразметка schema.org

Формат — JSON-LD, размещать в `<head>`. Ниже — рабочие шаблоны под прокат
(модель для аренды: `Offer.businessFunction = LeaseOut` — стандартный способ
пометить оффер как аренду, а не продажу). **Все значения (телефон, адрес,
координаты, цены) — плейсхолдеры, заменить на реальные данные ВОЛЬТ перед
публикацией.**

### 4.1 Organization + LocalBusiness (главная / `/contacts` / `/krasnoyarsk`)

```json
{
  "@context": "https://schema.org",
  "@type": "LocalBusiness",
  "@id": "https://volt-rent.netlify.app/#business",
  "name": "ВОЛЬТ — аренда инструмента APEXWOLT",
  "alternateName": "ВОЛЬТ прокат инструмента",
  "url": "https://volt-rent.netlify.app/",
  "image": "https://volt-rent.netlify.app/og-image.jpg",
  "logo": "https://volt-rent.netlify.app/logo.png",
  "telephone": "+7-XXX-XXX-XX-XX",
  "priceRange": "$$",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "УТОЧНИТЬ",
    "addressLocality": "Красноярск",
    "addressRegion": "Красноярский край",
    "postalCode": "УТОЧНИТЬ",
    "addressCountry": "RU"
  },
  "geo": {
    "@type": "GeoCoordinates",
    "latitude": 56.0184,
    "longitude": 92.8672
  },
  "areaServed": [
    { "@type": "City", "name": "Красноярск" }
  ],
  "openingHoursSpecification": [
    {
      "@type": "OpeningHoursSpecification",
      "dayOfWeek": ["Monday","Tuesday","Wednesday","Thursday","Friday","Saturday","Sunday"],
      "opens": "09:00",
      "closes": "20:00"
    }
  ],
  "sameAs": [
    "https://2gis.ru/krasnoyarsk/firm/УТОЧНИТЬ",
    "https://yandex.ru/maps/org/УТОЧНИТЬ",
    "https://t.me/УТОЧНИТЬ"
  ]
}
```

Для каждого пункта выдачи (`/punkty-vydachi/{город}`) — отдельный блок
`LocalBusiness` с `@id`, ссылающийся на головную организацию через
`parentOrganization`, и своим `address`/`areaServed`.

### 4.2 Product + Offer (аренда, не продажа)

### 4.5 Приоритет внедрения

1. `LocalBusiness` на главной/контактах — фаза 0–30 (напрямую влияет на
   локальную выдачу и панель знаний).
2. `BreadcrumbList` + `Product/Offer` на карточках — фаза 0–30 (шаблон) /
   31–60 (массовое наполнение по мере роста каталога).
3. `FAQPage` — фаза 0–30 вместе с созданием `/faq`.
4. Дополнительные `LocalBusiness` на страницах пунктов выдачи — фаза 31–60.

После внедрения — обязательная проверка через **Google Rich Results Test**
(не через простой fetch: JS-инжектированную разметку статический краулер
может не увидеть — проверять рендер).

## 5. Локальное SEO

### 5.1 Карты и справочники — обязательный минимум

| Площадка | Действие | Фаза |
|---|---|---|
| Яндекс Бизнес (Яндекс Карты) | Завести/актуализировать карточку: категория «Прокат инструмента», адрес, телефон, часы, фото, ссылка на сайт и Telegram-бот заказа | 0–30 |
| 2ГИС | Карточка организации, категория «Прокат строительного оборудования / инструмента», рубрики по каждому типу инструмента если позволяет структура 2ГИС | 0–30 |
| Google Business Profile | Карточка с адресом, услугами (перфораторы, УШМ и т.д. как «услуги»), фото инструмента | 0–30 |
| Zoon.ru | Локальная карточка услуг проката | 31–60 |
| Flamp (через 2ГИС) | Подключить сбор отзывов | 31–60 |
| Профильные каталоги Красноярска (например, list-org, справочники «Стройка/Ремонт Красноярск») | Разместить карточку компании со ссылкой на сайт | 31–60 |
| Avito (раздел «Услуги» / «Прокат инструмента») | Разместить объявления по категориям с ссылкой на сайт — доп. канал трафика и сигнал присутствия | 31–60 |
| Профильные тематические форумы/агрегаторы стройуслуг Красноярска | Точечное размещение, если есть бесплатные разделы | 61–90 |

### 5.2 NAP-консистентность (Name-Address-Phone)

- Зафиксировать единый эталон: название компании («ВОЛЬТ» / «ВОЛЬТ — аренда
  инструмента APEXWOLT»), точный адрес, телефон, часы работы — в одном
  документе (справочный лист), и использовать **дословно одинаково** на
  всех площадках (сайт, Яндекс, 2ГИС, Google, каталоги).
- Любое расхождение в написании адреса/телефона снижает доверие
  геосервисов и размывает сигнал локальной релевантности.
- Тот же эталон — источник для `LocalBusiness` JSON-LD (раздел 4.1).

### 5.3 Отзывы

- Просить отзыв после каждой сделки через Telegram-бот (саппорт-бот) —
  прямая ссылка на форму отзыва в Яндекс/2ГИС/Google.
- Отвечать на все отзывы (в т.ч. негативные) — сигнал активности бизнеса.
- На гео-хабе `/krasnoyarsk` и карточках товаров — блок с виджетом/цитатами
  отзывов (если технически возможно на статике — верстка блока вручную с
  реальными отзывами, без выдумывания).

### 5.4 Гео-контент под Красноярск и пункты выдачи

- На `/krasnoyarsk` — упоминание районов доставки (если ВОЛЬТ везёт по
  всему городу — так и написать; если есть ограничения зоны — указать
  честно).
- На страницах пунктов выдачи — реальный адрес, ориентир, часы работы,
  фото точки выдачи (если есть).
- В Title/H1 гео-страниц — топоним на первом месте после интента
  («Аренда инструмента в Братске», не «Братск: аренда инструмента»).

## 6. Технический минимум

| Область | Что сделать | Почему |
|---|---|---|
| **robots.txt** | Создать `/robots.txt`: разрешить обход всех публичных разделов, закрыть служебные (если появятся `/admin`, `/api`), указать `Sitemap: https://volt-rent.netlify.app/sitemap.xml` | Сейчас файла нет вообще — базовый пробел |
| **sitemap.xml** | Сгенерировать (статически, на этапе сборки — Netlify это позволяет) со всеми публичными URL, обновлять при каждом добавлении категории/товара/статьи | Ускоряет индексацию, обязателен для Search Console/Я.Вебмастера |
| **Индексация SPA-контента** | Проверить, рендерится ли `/catalog` и карточки в статический HTML при сборке (SSG/prerender) или требуют JS. Если контент подгружается только через JS без пререндера — **это критичный риск**: часть каталога может не индексироваться | На срезе (раздел 0) страница каталога вернула «в категории пока нет позиций» даже в статическом ответе — нужно перепроверить рендер в браузере/Rich Results Test и, если подтвердится, перейти на статическую генерацию (SSG) категорий/карточек |
| **Скорость и Core Web Vitals** | Прогнать через PageSpeed Insights (мобайл в приоритете), оптимизировать изображения инструмента (WebP, сжатие, lazy-load на некритичных), проверить LCP/CLS/INP | Netlify отдаёт статику быстро по умолчанию, но тяжёлые фото инструмента — типичная просадка LCP |
| **Мобильная версия** | Проверить тап-зоны кнопок заказа, отсутствие горизонтального скролла, читаемость каталога на мобильном (основной трафик локального спроса — мобильный) | Mobile-first индексация |
| **HTTPS** | Уже обеспечивается Netlify по умолчанию — проверить отсутствие смешанного контента (http-ресурсы на https-странице) | Базовое требование |
| **Канонические URL** | Прописать self-canonical на каждой странице, единая политика по слэшу в конце URL | Профилактика дублей при будущем росте каталога |
| **Регистрация в вебмастерах** | Добавить сайт в Яндекс.Вебмастер и Google Search Console, отправить sitemap, отслеживать покрытие индексации | Обязательный шаг для мониторинга, без него SEO слепое |
| **Alt-тексты изображений** | Прописать по шаблону «{инструмент} {модель} — аренда в Красноярске» на все фото товаров | Изображения инструмента — доп. источник трафика (картинки в поиске) |
| **llms.txt (минимальный, задел под ИИ-поиск)** | Добавить `/llms.txt` с кратким описанием бизнеса, ассортимента, оффера и ссылками на ключевые страницы (каталог, гео-хаб, FAQ, условия) | Дешёвый шаг, помогает ИИ-агентам (ChatGPT/Perplexity/Claude) корректно описывать ВОЛЬТ; не требуется для Google AI Overviews, но не мешает и не заменяет качественный контент |

## 7. План работ по фазам

### Фаза 0–30 (фундамент)

**Приоритет: критичное — без этого дальнейшее продвижение неэффективно.**

1. Снять реальные частотности по семантике раздела 1 (Яндекс.Wordstat +
   Google Keyword Planner, гео = Красноярск) — уточнить приоритет категорий.
2. Создать `robots.txt` + `sitemap.xml`, подключить Яндекс.Вебмастер и
   Google Search Console.
3. Проверить рендер `/catalog` и карточек (JS vs статика) — при
   необходимости перевести на SSG/пререндер.
4. Создать 6 страниц категорий (`/catalog/{категория}`) с шаблоном из
   раздела 3.1, добавить их в навигацию каталога и на главную.
5. Создать гео-хаб `/krasnoyarsk` (раздел 3.3).
6. Создать `/faq` со сводом возражений, внедрить `FAQPage` JSON-LD.
7. Внедрить `LocalBusiness` JSON-LD на главной/контактах (раздел 4.1) с
   реальными NAP-данными.
8. Внедрить `BreadcrumbList` на всех страницах глубже 1-го уровня.
9. Завести/актуализировать карточки в Яндекс Бизнес, 2ГИС, Google Business
   Profile с едиными NAP-данными (раздел 5.1–5.2).
10. Прописать title/description/H1 по шаблонам раздела 3 на все
    существующие страницы (`/`, `/catalog`, `/terms`, `/contacts`).

### Фаза 31–60 (масштабирование)

1. Наполнить карточки товаров (`Product/Offer` JSON-LD, реальные
   характеристики) по мере роста каталога — приоритет категориям с
   наибольшим подтверждённым спросом (обычно перфоратор/УШМ/шуруповёрт).
2. Создать хаб `/punkty-vydachi` и 3 страницы пунктов выдачи (Братск,
   Усть-Илимск, Нижнеудинск) по шаблону раздела 3.4, с отдельными
   `LocalBusiness` блоками.
3. Запустить `/blog` с первыми 4–6 материалами под информационные ключи
   раздела 1.2 (по одному-два на самые частотные категории: перфоратор,
   УШМ, шуруповёрт) — с перелинковкой на соответствующие карточки/категории.
4. Разместить карточки на Zoon, Avito (услуги), профильных каталогах
   Красноярска (раздел 5.1).
5. Запустить сбор отзывов через саппорт-бот, начать отвечать на все отзывы.
6. Прогнать технический аудит скорости/CWV, устранить топ-3 проблемы.
7. Добавить `llms.txt`.

### Фаза 61–90 (закрепление и рост)

1. Донаполнить блог до 10–12 материалов, закрыть оставшиеся
   информационные кластеры и сравнения («перфоратор или дрель», «болгарка
   125 или 230» и т.п.).
2. Расширить FAQ-блоки на страницах категорий на основе реальных вопросов
   из саппорт-бота (живая семантика от клиентов — ценнее прогнозной).
3. Точечные размещения в оставшихся тематических каталогах/форумах
   Красноярска и городов пунктов выдачи.
4. Ревизия каннибализации ключей между категориями/гео-страницами/блогом
   по данным Search Console — при пересечениях уточнить фокус страниц.
5. Повторный технический аудит (Core Web Vitals, покрытие индексации,
   ошибки в Search Console/Я.Вебмастере) — фиксация базовой линии для
   следующего 90-дневного цикла.
6. Проверка видимости бренда в ИИ-поиске (ChatGPT/Perplexity/Яндекс с ИИ)
   по запросам «аренда инструмента Красноярск» — ручной ежемесячный чек,
   без отдельного бюджета на инструменты мониторинга.

## Итог

Сайт сейчас — «визитка + каталог» без SEO-фундамента: нет robots/sitemap,
нет страниц категорий и гео-страниц, нет schema, есть риск неполной
индексации JS-каталога. План закрывает это по приоритету: фаза 0–30 —
техническая база + 6 категорий + гео-хаб Красноярск + LocalBusiness/FAQ
разметка; фаза 31–60 — карточки товаров, пункты выдачи, блог, справочники,
отзывы; фаза 61–90 — контентное расширение, устранение каннибализации,
повторный аудит. Приоритет везде — реальные данные сайта и прайса, без
выдуманных цен и характеристик.
