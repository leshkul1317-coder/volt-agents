   `product_view`, `cta_rent_click`, `cta_telegram_click`, `tariff_switch`,
   `support_bot_click`, `scroll_75` (см. план §D.2). Нужен логин/доступ на просмотр
   (роль «Читатель» достаточно) — источник для **блока 1 и 2**.
2. **Выгрузка лога заказ-бота в Google Sheets** по схеме `context/leads-sheet-schema.md`
   (лист «Заявки»). Пока заявки лежат только в Telegram-переписке — без выгрузки
   не посчитать ни один из блоков 3–5. Нужно решить способ подключения (Apps Script /
   n8n / прямой API — варианты в схеме) и дать доступ на чтение таблицы.
3. **UTM-разметка / `?start=` коды по каналам** — сейчас не используются (`TODO` в

   невозможны. Минимум для старта: разные `?start=` коды заказ-бота на каждый канал
   (VK, 2ГИС, Телеграм-канал, Директ) — правило «ни одной ссылки без UTM/кода».
4. **Статус A/B-тестов #1, #2, #5** — подтверждение, что варианты CTA/бейджа/автоответа
   бота реально включены на сайте/в боте, и дата старта каждого — для блока 6.

## Гипотезы и что проверить на этой неделе

Исходя из этапа плана (фаза 0–30 — точка отсчёта ещё не снята, критический риск №1
плана — отсутствие CAC/конверсии для бюджетных решений §A):

1. **Проверить рендер `/catalog` (SSG vs JS) через Rich Results Test.** Если каталог не
   индексируется — это не просто SEO-проблема, а причина того, почему органический и
   картовый трафик (блок 1) может быть занижен уже сейчас, до всякой аналитики. Дешёвая
   проверка (1 запрос в Google Rich Results Test), высокий потенциальный эффект —
   делаем в первую очередь на этой неделе.
2. **Гипотеза по точке потери «карточка → клик CTA».** План (§D.3) называет её главной
   точкой потери в модели: не видно сразу цены по тарифам, залога и условий доставки.
   Проверить эмпирически без ждать А/Б-теста: пройти путь клиента на 3–5 карточках
   товаров глазами клиента (мобильный экран) и зафиксировать, видны ли без скролла —
   цена, бейдж «доставка от 3 дней», статус наличия. Это подготовит контент для теста
   #2, который и так запланирован на эту фазу.
3. **Гипотеза по deep-link/`?start=`-кодам как быстрому заменителю UTM.** Пока Netlify
   Function (фаза 31–60) не готова, дешёвый способ увидеть канал в заявке уже сейчас —
   раздать уникальные `?start=` коды по 3–4 активным каналам (VK, 2ГИС, Telegram-канал,
   Директ, если есть) и попросить оператора бота фиксировать `start_param` в таблице.
   Если это сделать на этой неделе — со следующего отчёта блок 1 частично оживёт даже
   без полноценной выгрузки Метрики.
